## Подключение уже выполнено; инструкция для повторной настройки

1. Открыть [@BotFather](https://t.me/BotFather), выполнить `/newbot`, выбрать имя и свободный username с окончанием `bot`. Нужен отдельный бот, не используемый другими сервисами.
2. В канале `@nisphysicshub` добавить этого бота администратором. Для чтения публикаций не нужны права удалять/редактировать сообщения; можно оставить минимальные доступные права.
3. Открыть [Edge Functions → Secrets](https://supabase.com/dashboard/project/gotlcaqzrwfitgiwmsnj/functions/secrets) проекта. Сохранить секрет с именем **`TELEGRAM_BOT_TOKEN`**, значение — токен из BotFather. Не отправлять токен в чат, не помещать его в `.env` интерфейса или `VITE_*`.
4. Написать агенту «бот добавлен, секрет сохранён». Агент выполнит одноразовую серверную настройку через `telegram-setup` и снова закроет её. Не нужно присылать токен или service-role key.
5. После настройки опубликовать обычную новую запись в канале и проверить её появление/редактирование в общем чате. До этого нельзя считать доставку реально проверенной.

Серверная настройка проверяет `getMe`, `getChat`, статус администратора через `getChatMember`, привязывает настоящий numeric `chat_id`, регистрирует `setWebhook` только для `channel_post`/`edited_channel_post`. Если бот уже обслуживает чужой webhook, настройка откажется заменять его. Pending updates не сбрасываются.

`TELEGRAM_WEBHOOK_SECRET` необязателен: по умолчанию сервер вычисляет SHA-256 от фиксированного префикса и секретного токена. Тот же секрет передаётся Telegram при настройке и сверяется с `X-Telegram-Bot-Api-Secret-Token` ДО обработки тела/запросов к базе. Секрет не хранится в публичных таблицах.

## История с файлами — после установки Telegram Desktop

Текущий ZIP уже перенесён. Для недостающих файлов раннего периода нужен дополнительный экспорт канала с начала истории, желательно JSON (`result.json`) и папки вложений. HTML тоже поддерживается. Выбрать весь период, фото, видео и документы. Не включать другие личные чаты.

Импортёр HTML реализован в `scripts/telegram-export.mjs`: сохраняет ID, текст, UTF-16-форматирование и исходные файлы. JS/обработчики из экспорта никогда не выполняются. Слой `source_kind='export'` сохраняет приоритет правок бота. Два времени веб-версии отличаются от экспорта на одну секунду при полностью одинаковом тексте — в этих случаях сохранён канонический timestamp существующей записи для стабильной пагинации. Текущий экспорт сопоставлен по имени канала и временным меткам 158 общих ID. Прямой JSON-адаптер ещё не реализован.

Bot API получает новые события и не выдаёт всю старую историю. Облачный `getFile` ограничивает загрузку 20 МБ: крупные/неподдерживаемые вложения остаются ссылкой на оригинал, текст при этом публикуется. Удаления постов не доставляются Bot API как `deleted_channel_post` — зеркальное удаление потребует отдельного решения. См. [Telegram FAQ](https://core.telegram.org/bots/faq) и [Bot API](https://core.telegram.org/bots/api).
