# Посты TerenPhys в Supabase
Данные находятся в проекте gotlcaqzrwfitgiwmsnj. Таблицы и RLS уже опубликованы.
Профили: profiles, лента: posts, права авторов: post_authors.
Новых авторов назначает администратор, а не пользователь из браузера.

## Назначить автора
1. Автор регистрируется, подтверждает почту и открывает свой профиль.
2. В Authentication → Users скопировать UUID его аккаунта.
3. В Table Editor → post_authors добавить отдельную строку для каждого класса:
   user_id = UUID автора, grade = любой класс от 7 до 12, is_active = true.
4. Автор обновляет страницу или выбирает класс заново.
Чтобы отозвать право, выставить is_active = false в нужной строке.
Если нужен доступ к двум классам, создать две строки с одним user_id и разными grade.

Публиковать может только подтверждённый пользователь с активной записью на этот класс.
Роль в user_metadata, изменение ника или запрос прямо к API не дают дополнительных прав.
Сервер заполняет author_name, author_avatar_path и created_at.
Клиент отправляет только grade, text и author_id. Максимальная длина — 2000 символов.
Лента выбирает 100 последних постов класса, сортировка по server created_at и id.
Realtime обновляет ленту без ручной перезагрузки.

## Общий чат Telegram

Отдельная read-only лента канала @nisphysicshub: `telegram_posts`, `telegram_sources`, bucket `telegram-media`.
Сайт не выдаёт участникам право публиковать от имени Telegram. Авторские записи `posts` по-прежнему привязаны к выбранному классу и прежним правам; в классовой ленте они показаны вместе с подходящими публикациями Telegram в хронологическом порядке.
Статус переноса и необходимые шаги для бота — в [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md).
Вложения одной публикации показаны единым списком. PDF/DOCX и фото открываются на сайте, отдельная кнопка скачивает оригинал. Архивные группы восстанавливаются в UI консервативно, без удаления или слияния строк базы; новые альбомы используют Telegram media_group_id. Файлы, которых нет в хранилище, остаются ссылками на их исходное сообщение.

## Автоматическая сортировка Telegram по классам

Используйте `#7класс`, `#8класс`, `#9класс`, `#10класс`, `#11класс`, `#12класс`. Казахские `#7сынып` / `#сынып7` и варианты с подчёркиванием тоже распознаются; регистр не важен. Несколько хештегов класса показывают запись в каждом указанном классе. При отсутствии распознанного хештега класса запись видна во всех 7–12 классах, даже если есть тематические теги вроде `#сор`. Общий чат остаётся полной лентой.

Правило применяется к всей истории, новым сообщениям и правкам при чтении/realtime без копирования строк или файлов. `telegramGrades` и `telegramMatchesGrade` находятся в `src/telegram/model.ts`. Сначала объединяется альбом, затем учитывается совокупность его хештегов: файлы без собственной подписи не становятся общими. Загрузка класса в `api.ts` продвигает исходный курсор до достаточного числа подходящих сообщений; один запрос UI ограничен десятью исходными страницами, остаток доступен через «Ранее». Фильтр применяется повторно при отрисовке после realtime-правок. При смене класса компонент ленты получает новый key, чтобы исключить прежние данные/курсоры. RLS, webhook, RPC и база не изменены.
