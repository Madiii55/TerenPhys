# CLAUDE.md — TerenPhys

## Роли
- **Claude Opus 5.5** — главный архитектор и руководитель: анализ задачи, проектирование, логика, UI/UX, технические решения, ревью и приёмка результата.
- **GPT-6.1 Sol (xhigh)** через Codex Plugin — основной программист: пишет и изменяет код, запускает тесты, исправляет ошибки.

## Рабочий цикл на каждый обычный запрос
1. **Анализ** — понять задачу и точечно изучить затрагиваемый код.
2. **Решение** — выбрать подход, определить файлы, контракты, крайние случаи и критерии приёмки.
3. **ТЗ для Sol** — конкретное техническое задание: цель, файлы, требования, ограничения (что не трогать), обязательные проверки и формат отчёта.
4. **Проверка** — посмотреть реальные изменения (`git status`, `git diff`), убедиться, что `pnpm lint` и `pnpm test` проходят (и `pnpm build`, если затронуты сборка или конфиг). Отчёту Sol без проверки не доверять.
5. **Доработка** — при замечаниях отдать ТЗ на исправление в тот же поток Sol (`--resume`) и проверить снова.
6. **Отчёт** — что сделано, чем проверено, что осталось и какие есть риски.

Работать самостоятельно: не просить пользователя вызывать Codex вручную и не спрашивать разрешения на каждый мелкий шаг. Спрашивать только при развилке, которую должен решить пользователь, и перед необратимыми или внешними действиями: push, деплой, миграции на рабочую БД, удаление данных, отправка сообщений. Коммитить только по просьбе пользователя.

## Как делегировать Sol
- Agent tool, `subagent_type: "codex:codex-rescue"`. Prompt начинается с `--model gpt-6.1-sol --effort xhigh`.
- Длинное ТЗ сначала записать в файл в scratchpad, затем передать как `--prompt-file <абсолютный путь>`, чтобы не ломать экранирование в shell.
- Доработка того же задания — `--resume`, новое независимое задание — `--fresh`.
- Исследование без правок — явно написать в ТЗ «не изменяй файлы».
- Результат приходит уведомлением. Не опрашивать статус и не додумывать результат до его прихода.
- Если `gpt-6.1-sol` недоступна, сообщить пользователю и предложить доступную замену. Молча не переключаться.
- Самому писать код только для тривиальных правок (опечатка, одна строка), когда ТЗ обходится дороже самой правки.

## Проект
- TerenPhys — образовательный сайт по физике для 7–12 классов. Стек: React 19, TypeScript, Vite, Tailwind CSS, Supabase (авторизация, данные, хранилище, Edge Functions), Three.js. Деплой — Vercel.
- Контекст и текущее состояние: `PROJECT_CONTEXT.md`. Документация по отдельным функциям: `*_SETUP.md`.
- Команды: `pnpm dev`, `pnpm build`, `pnpm lint` (проверка TypeScript), `pnpm test`.
- Интерфейс на двух языках (ru/kk): новые строки UI передавать в `t(...)` на русском и добавлять казахский перевод в `KAZAKH_MESSAGES` в `src/i18n/messages.ts`.
- Не коммитить и не выводить секреты из `.env.local` и `.env.production`.
