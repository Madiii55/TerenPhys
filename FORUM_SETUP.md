# Форум TerenPhys

Форум подключён к Supabase project gotlcaqzrwfitgiwmsnj.
Применены миграции forum_topics_comments_likes_views и forum_private_views_policy.
supabase/forum-schema.sql — снимок добавленной схемы, не запускайте повторно поверх рабочей базы.

## Возможности
- Последние: created_at DESC; популярные: view_count DESC; лучшие: like_count DESC.
  При равенстве метрик используется дата и стабильный ID.
- Фильтры: 7–12 классы и основные разделы физики. «Все» включает темы без привязки к классу.
- Поиск по заголовку и тексту: PostgreSQL FTS, словарь russian, websearch, GIN-индекс.
- Лента разбита на страницы по 15 тем.
- В теме отображаются текст, автор, дата, просмотры, лайки и комментарии.
- Ответ на комментарий хранит parent_id. Составной внешний ключ запрещает ответ в другую тему.
- Комментарии загружаются порциями; новые ответы и счётчики обновляются через Realtime.
- На мобильных разделы листаются горизонтально внутри панели; вся страница не переполняется.

## Данные и доступ
public.forum_topics: темы и агрегированные счётчики.
public.forum_comments: комментарии и ответы.
public.forum_likes: один лайк аккаунта на тему; читать можно только свои записи.
private.forum_views: закрытый журнал для дедупликации просмотров.

Гости читают темы/комментарии и пользуются фильтрами. Публикация, ответы, лайки и отмена лайка
разрешены только пользователям с подтверждённой почтой. Это проверяется RLS на сервере.
Назначение post_authors для форума не требуется: оно относится только к учебным постам.
Имя/аватар автора и дата формируются сервером, счётчики нельзя прислать или изменить из клиента.
Тексты выводятся как обычный текст React, без исполнения HTML.

Счётчик просмотров увеличивается через узкую RPC forum_record_view: не чаще одного раза
за 24 часа для пары тема + аккаунт, а у гостей — тема + случайный ID браузера.
ID гостя хранится локально. Это защита от обычных повторных открытий, не полноценная защита от ботов:
очистка данных браузера создаёт новый ID. IP-адреса не сохраняются.

## Проверки
- TypeScript, production build, существующий набор тестов.
- supabase/forum-security-check.sql: реальные проверки RLS, публичного чтения, публикации участником,
  запрета записи гостю/неподтверждённому аккаунту, подмены автора/счётчиков,
  повторных лайков, отмены лайка, ответа в другую тему и дедупликации просмотров.
  Все тестовые записи откатываются через ROLLBACK.
- tests/fixtures/forum.html — изолированный стенд с демонстрационным адаптером.
  Проверены поиск, фильтры, сортировки, входной барьер гостя, создание темы,
  комментарий-ответ, лайк и мобильный макет. Стенд не пишет в Supabase и не входит в production build.
- Полный цикл регистрации по реальному письму не входит в эти проверки; SMTP остаётся отдельной
  настройкой из AUTH_SETUP.md.

При проверке advisors сообщения unused_index на пустых таблицах ожидаемы; индексы нужны для
фильтрации, сортировки, поиска и внешних ключей. Не удаляйте их лишь из-за отсутствия реальных тем.
